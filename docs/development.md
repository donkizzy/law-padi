# Development

The basic setup (environment files, database, API and frontend) is in the
[README](../README.md#running-locally). This page covers the rest.

## Local services and ports

| Service | How | URL |
| --- | --- | --- |
| Frontend (Vite) | `bun run dev` | <http://localhost:5173> |
| API and OpenAPI docs | `cd backend && uv run fastapi dev` | <http://localhost:8000/docs> |
| PostgreSQL with pgvector | `docker compose up -d db` | `localhost:5432` |
| Mailpit (captured email) | `docker compose up -d mailpit` | <http://localhost:8025> |
| Adminer | `docker compose up -d adminer` | <http://localhost:8080> |

The backend reads the repository-root `.env` and the frontend reads
`frontend/.env`. Both are git-ignored; copy them from the tracked
`.env.example` files.

## Workers

- **Chat worker.** Answers are generated by a separate process locally:
  `cd backend && uv run python -m app.chat.worker`, or `docker compose up -d chat-worker`.
  It needs `CHAT_ENABLED=true`, `CHAT_GENERATION_ENABLED=true` and a
  `DEEPSEEK_API_KEY`. `compose.ai.yml` overlays a one-generation, low-budget
  preview:
  `docker compose -f compose.yml -f compose.override.yml -f compose.ai.yml up -d backend chat-worker`.
- **Ingestion worker.** PDF rendering and OCR need Poppler and Tesseract, which
  the `ingestion-worker` image provides: `docker compose up -d ingestion-worker`.
  Act ingestion is opt-in through `INGESTION_ALLOWED_INSTRUMENT_TYPES`. The
  procedure is in [`runbooks/ingestion.md`](runbooks/ingestion.md).

A fresh database has no published law. Search, reading and chat need a corpus
release ingested and published through the admin workspace; the source PDFs are
not in this repository.

## Full stack in Docker Compose

```bash
docker compose run --rm backend bash scripts/prestart.sh
docker compose watch
```

`compose.yml` holds the shared configuration and `compose.override.yml` adds
local ports, source sync and reloads. The Compose backend serves the built
frontend at <http://localhost:8000>; stop a local `fastapi dev` first because
both use port 8000. `compose.deploy.yml` is the self-hosted deployment overlay
with Traefik and TLS; production does not use it.

## Tests

- Backend: `cd backend && uv run bash scripts/test.sh`. The runner creates and
  migrates a database whose name ends in `_test` and refuses any other name. Set
  `TEST_DATABASE_URL` to use a different test database. Pytest arguments are
  passed through.
- Deployment helpers: `uv run python -m unittest discover -s deployment/tests`.
- Cloudflare Worker: `bun test deployment/cloudflare/worker.test.ts deployment/cloudflare/public-pages.test.ts`.
- Browser tests: `bun run test` runs Playwright against the Compose stack.

## Generated code

- Frontend API client: `bash scripts/generate-client.sh` after changing backend
  routes or schemas. Do not edit `frontend/src/client/` or
  `frontend/src/routeTree.gen.ts` by hand.
- Email templates: sources are in `packages/react-email/`; `bun run email:export`
  regenerates `backend/app/email-templates/`.

## Git hooks

The hooks in `.pre-commit-config.yaml` run with [prek](https://prek.j178.dev/):
`uv run prek install -f` once, then they run on each commit; `uv run prek run --all-files`
runs them by hand. They report problems and, apart from whitespace fixes, do not
rewrite files.
